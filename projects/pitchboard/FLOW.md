### 추천: J1 "지금 피칭할 수 있는, 돈 주는 매체 찾기" (검색이 중심 행동)
한 문장: **"서평·비평을 쓰는 프리랜서가, 매체 이름·지급·지역으로 검색하거나 '지금 열림'을 눌러 피칭할 곳을 찾는다."**
이유 [추정]: 데이터 자산이 곧 검색 가능한 표이고, 스폰서·뉴스레터 수익도 이 표를 보러 오는 방문자에서 나온다. 구독(J3)은 J1을 마친 사람의 후속 행동이므로 첫 화면 주인공이 아니라 표 아래로. J2는 "곧 마감" 한 줄 요약으로 보조.
준태님 지시의 "검색이 목적이면 가운데 큰 검색창"에 해당. **[짐작]** 방문자가 매체 이름을 알고 오는지 조건("open"·"pays")으로 탐색하는지 비율은 모름(분석 도구 금지 규칙으로 측정 불가).

## 3. 추천안 첫 화면 와이어 (c) — 모바일 우선

```
┌ 390px ─────────────────────────┐
│ The Pitchboard        [≡ Menu]  │  ← 내비 7개 → Directory · Calls · Newsletter · ≡(Advertise, Methodology, About)
│                                │      (홈에서는 헤더 검색창 제거)
│ Where to pitch book reviews     │  ← 정체성: 현재 h1 유지
│ and cultural criticism.         │
│ 93 outlets · every fact dated   │  ← 리드 4줄 → 1줄
│                                │
│ ┌────────────────────────────┐ │
│ │ 🔍 Search by name, pay, region│ │  ← 큰 검색창 (1차) 높이 ≥ 48px
│ └────────────────────────────┘ │
│ (Open now 29) (Pitch first 41)  │  ← 상태 칩: 기존 stats 4개를 칩으로 (눌러서 필터)
│ Closing soon: Brick · Oct 31 ›  │  ← 2차: calls.json 가장 가까운 마감 1줄 → /calls/
└────────────────────────────────┘
(스크롤 후) 표: 8행 (Outlet · Status · Pay · Checked), 모바일은 행 카드 형태
           [ See all 93 outlets ]
(스크롤 후) 스폰서 칸(라벨 유지) → 구독 박스(beehiiv)
```
- 1차 CTA = 검색(+ 상태 칩이 바로 필터), 2차 = "Closing soon" 한 줄(Calls로). 현재의 버튼 3개는 제거(검색·칩·한 줄로 대체).
- 목표: 첫 화면 링크 ≤ 8, 단어 ≤ 45, 표 시작이 첫 화면 또는 바로 아래 [설계 목표, 구현 후 재측정].
- 흐름: 홈 → (칩 또는 검색) → 결과 → 아웃렛 상세 = 2클릭. 상세 → 다음 아웃렛 = 1클릭(§5 "Similar open outlets" 추가 후).
- 상세 페이지의 1차 행동: 지금은 "Links" 항목 안에 묻힌 "Pitch guidelines (outlet)"를 **상단 버튼 1개**로.

## 4. 제품 기능 제안과 제약 검토 (d)

규칙 [문서]: 의존성 추가 금지, 트래커 금지, last-checked + 90일 stale 배지 유지, 스폰서 항상 표시·라벨, beehiiv 폼 유지, `data/` 수정 금지, 데이터 문구 수정 금지.

| 제안 | 라벨 | 설명 |
|---|---|---|
| 홈 큰 검색창 → `/outlets/?q=` | **정적 사이트로 가능** | `app.js`가 이미 `?q=`/`?status=`를 읽는다 [측정, app.js 9줄]. GET 폼으로 충분. 의존성 없음. |
| 상태 칩(Open now / Pitch first) | **정적 사이트로 가능** | 기존 `?status=` 링크. 숫자는 빌드 시점 값. |
| "Closing soon" 한 줄 | **정적 사이트로 가능** | `calls.json`의 마감일을 빌드에서 선택. "N days left"는 빌드 이후 낡으므로 날짜만 표기(또는 작은 JS). 빌드 주기와 일치해야 함 → pitchboard 봇이 재빌드 루틴 확인 필요 [짐작]. |
| 지급액 정렬/필터(예: $200+) | **불가(데이터 필요, 결정 필요)** | `pays`가 자유 문장("$250-$1,000 for prose…") 형태라 프론트에서 안전하게 숫자 파싱 불가. 정렬하려면 봇에 숫자 필드(`pay_min` 등) 요청. 프론트가 데이터 문구를 바꾸지 않음. |
| 상태·지역 필터 노출 방식 개선(칩) | **정적 사이트로 가능** | 기존 select를 칩으로. |
| "Similar open outlets"(같은 지역·같은 상태 3곳) | **정적 사이트로 가능** | 빌드 시 `outlets.json`에서 계산. 데이터 수정 없음. |
| 마감일 달력 `.ics` 다운로드 | **정적 사이트로 가능** | 빌드에서 `calls.json`으로 생성. 의존성 없음. |
| 저장(북마크) | **정적 사이트로 가능(결정 필요)** | `localStorage`. "no accounts" 방침과 일치하나 신규 기능 결정 필요. |
| 사용자 후기("I got paid X")·좋아요 | **백엔드 필요(준태님 결정 필요)** | 서버·검수 필요. 가짜 후기 금지 원칙, 트래커 금지와 충돌 가능. 지금은 권장하지 않음. |
| 글쓰기 | **해당 없음** | 매체 디렉터리이며 콘텐츠는 pitchboard 봇이 관리. |
| 위치 기반 | **해당 없음** | 장소 서비스 아님(지역 select만). |
| 정정 제보 폼 | **백엔드 필요/현행 유지** | 현재 mailto. 폼은 서버 필요. |
