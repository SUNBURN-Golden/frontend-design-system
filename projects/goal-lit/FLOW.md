### 추천: J1 (작품을 알아보고 → 그 작품의 평론 한 편을 읽기)
한 문장: **"한국 문학·웹툰·웹소설 작품에 대해 평단·매체가 뭐라 했는지 궁금한 독자가, 대표 평론 한 편을 바로 열어 읽는다."**
이유 [추정]: (1) 모든 콘텐츠가 작품 단위로 묶여 있고, (2) 평론 29편 규모에서는 "읽을 글 고르기"보다 "내가 아는 작품 제목이 눈에 띄는 것"이 클릭 동기이며, (3) J3(추천)는 규칙상 못 하므로 사이트의 고유 약속("호평과 비판을 출처와 함께")을 바로 보여 주는 쪽이 낫다. J2는 J1의 결과(글)로 이어진다. 글 소비가 메인이므로 준태님의 "대표글 하나 바로 보이게" 원칙을 따른다.
**[짐작]** 실제 방문자가 작품 제목을 먼저 떠올리는지는 검증 데이터가 없음(트래픽 없음, noindex 프리뷰). 지인 3~5명 피드백(PLAN 6일차)에서 "첫 클릭이 뭐였나"를 물어 확인할 것.

## 4. 제품 기능 제안과 제약 검토 (d)

규칙 확인 [측정]: CSP `default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'none'`, 전 페이지 `x-robots-tag: noindex, nofollow`. `connect-src 'none'`이라 fetch/XHR로 JSON을 불러올 수 없고, 필요한 목록은 자체 `.js` 파일이나 HTML에 넣어야 한다.

| 제안 | 라벨 | 설명 |
|---|---|---|
| 대표글 1개 + 이어서 읽기 3줄 | **정적 사이트로 가능** | 이미 있는 `posts.json` 순서 사용. 데이터·문구 수정 없음. |
| 작품 종류 칩(소설/웹툰/웹소설/시·에세이) | **정적 사이트로 가능** | `works.csv`의 medium(소설 19, 웹툰 6, 웹소설 6, 소설집 4, 시집 4, 에세이 1) 기준 사전 생성 페이지(JS 불필요) 권장. |
| 작품 제목 검색창 | **정적 사이트로 가능** | 자체 호스팅 `.js`에 40개 작품 색인을 넣는 방식. CSP 통과. 필요성은 40편 규모에서 칩보다 낮음 [추정]. |
| 글 끝 "이어서 읽기"(같은 작품·같은 장르의 다른 글) | **정적 사이트로 가능** | 이름은 "추천"이 아니라 "같은 작품/같은 장르 글"로. 사이트 원칙 "추천을 매기지 않는다"와 충돌하지 않게 표기. |
| 추천 블록("이런 작품은 어때요") | **규칙 충돌** | PLAN 가드: 점수·추천 금지. 구현하지 않음. |

3. 좋아요·독자 후기·글쓰기는 백엔드·운영 체제가 필요해 지금은 미구현 권장. 하려면 별도 결정.

## 8. 측정하지 못한 것
- 실제 방문자의 첫 클릭 행동(트래픽·히트맵 없음). 5초 테스트는 실측 + 판단이며 사용자 테스트가 아님.
- 라이브가 아닌 `site_ui` 작업본(draft PR #1)의 첫 화면.
- 대비·터치 타겟의 전수 검사(이번 범위 밖, BEFORE_AUDIT.md 참고).
