# Goal Lit 한국어 문체 가이드 (ko-voice, 2026-10-19 KST, 2026-10-20 00:52 해요체로 정정)
목적: Goal Lit·HANSET의 문구(UI, 글 본문, 요약)를 한 사람의 목소리로 통일한다. 참조한 것은 평론가 신형철의 **문투**(문장의 태도와 리듬. 말투를 뜻하는 '어투'가 아니다)다. 공개된 서평·인터뷰·출판사 소개에서 자주 지적되는 특징을 요약했다. **그의 문장이나 구절은 옮기지 않는다.** 이 문서도 직접 인용을 하나도 싣지 않는다. 라벨: [공개자료 요약] [추정] [규칙].

## 1. 참조한 태도 (공개자료 요약)
1. **정확함이 윤리다.** 그는 비평의 덕목으로 '정확하게 말하기'를 거듭 앞세운다. 대상을 과장하지도, 깎아내리지도 않는 단어를 고르는 데 공을 들인다는 평이 많다 [공개자료 요약: 『정확한 사랑의 실험』 소개, 서평들].
2. **단정하되 겸손하다.** 판단은 분명하게 내리지만, 그것이 한 사람의 읽기라는 한계를 문장 안에서 숨기지 않는다 [공개자료 요약: 인터뷰·서평].
3. **리듬.** 짧은 단언 뒤에 그 단언을 풀어 주는 긴 문장이 온다. 문단 끝은 대개 짧게 닫힌다 [추정: 저서 소개와 서평에서 공통으로 묘사되는 특징].
4. **개념어를 쉽게 푼다.** 어려운 말을 쓰면 바로 다음 문장에서 일상어로 다시 말한다 [공개자료 요약].
5. **대상에 대한 존중.** 작품을 깎아내리는 재치보다, 작품이 하려던 일을 먼저 말한다 [공개자료 요약].
6. **상투어와 번역투를 멀리한다.** '~를 통해', '다양한', '의미 있는' 같은 기성 표현 대신 구체어를 쓴다 [추정].

## 2. 우리 규칙 (톤 통일안) [규칙]
- **화면의 모든 문장은 해요체 존댓말로 쓴다.** 글 요약, 소개, 원칙, 출처, 안내, 푸터, 빈 상태 문구가 모두 해당한다. 평서체 '-다'와 합니다체 '-습니다/-ㅂ니다'는 금지 어미다(`ko_lint.py`가 '어미 위반'으로 센다).
  - 근거: 2026-10-20 00:52 준태님 지시('사이트들은 전부 요체로 존댓말'). DISTILLED 17번(UI 해요체)과 아래 토스 원칙을 따른다. 앞서 쓴 '평서체 통일' 규칙(2026-10-19)은 이 지시로 폐기했다.
  - 예외: 인용된 평론 원문과 출처 제목, 준태님 원고(에세이 본문)는 쓰인 그대로 둔다. 제목형 헤드라인의 명사형 끝맺음, 운영 봇 소관 가드 고정 문구(5장)도 예외다.
  - 신형철의 문투(1장)는 **단어를 고를 때만** 참조한다. 정확한 단어를 쓰고, 과장하지 않고, 판단을 출처에 묶는다. 어미는 언제나 해요체다.
  - 적용 범위: Goal Lit, HANSET. HANSET의 운영 데이터(venues/events JSON·CSV)와 가드 고정 문구는 운영 봇이 바꾼다. Pitchboard는 영어 사이트라 이번 지시에서 뺐다(`tools/en_lint.py`).
- **토스 라이팅 원칙에서 가져온 것** [공개자료 요약: toss.tech '토스의 8가지 라이팅 원칙들', 앱인토스 consumer UX 가이드(studies/korean.md), DISTILLED 17]. 토스 문장은 옮기지 않고 원칙만 쓴다.
  1. **해요체로 통일한다.** 토스는 'Casual(친근한)' 원칙에 따라 딱딱한 합니다체 대신 해요체를 화면 전체에 쓴다. '~하시겠어요?' 같은 과한 경어는 쓰지 않는다.
  2. **짧게 쓴다.** 'Weed cutting'과 'Remove empty sentences'는 문장 속 군더더기와 화면 속 빈 문장을 덜어내라는 원칙이다. 한 화면에서 같은 말을 되풀이하지 않는다.
  3. **능동형으로 쓴다.** '~되었어요'보다 '~했어요'처럼 주체가 보이게 쓴다.
  4. **쉬운 말로 쓴다.** 'Easy to speak'와 'Universal words' 원칙에 따라 소리 내어 읽어 자연스러운 말을 고른다. 업계 용어나 한자어는 쉬운 말로 바꾼다.
  5. **사용자 관점으로 쓴다.** 'Focus on key message'와 'Predictable hint'를 따른다. 읽는 사람이 다음에 무엇을 하게 되는지 먼저 말하고, 버튼은 누르면 일어날 일을 이름으로 단다. 'Suggest over force'에 따라 명령보다 제안으로 쓴다.
- **버튼·내비·라벨은 문장이 아니라 명사구나 동사 어간으로 쓴다**(예: '평론 읽기', '작품 찾기'). 2~4어절로 하고 마침표는 찍지 않는다. CLEAN_RULES R3(첫 화면 60어절 이하)를 지킨다.
- **빈 상태·안내 문구는 짧은 해요체 한 문장으로 쓴다**(예: '아직 평론이 없어요').
- **'저는/우리는'은 쓰지 않는다.** 문장의 주어는 작품이나 매체로 둔다. 필명 에디터의 체험담은 금지다(레포 가드).
- **판단은 출처에 묶는다.** '~라고 평했어요', '~로 읽었어요'처럼 누가 그렇게 말했는지를 문장 안에 남긴다.
- **한 문장에 한 생각을 담는다.** 한 문장이 60자를 넘으면 쪼갤지 검토한다. 문단은 짧은 문장으로 닫는다.
- **바꾸지 않는 것:** 사실, 숫자, 날짜, 작품명, 매체명, 인용된 평론 원문, 출처 제목, 가드 고정 문구(5장).

## 3. 바꾸는 방향 (예시는 우리 사이트 문구로만 든다)
| 피할 것 | 쓸 것 | 이유 |
|---|---|---|
| ~를 통해 다시 읽어야 한다고 본다 | ~를 거쳐 다시 읽어야 한다고 봐요 / ~로 다시 읽자고 해요 | 번역투, 평서체 |
| ~에 대한 평가 | ~를 두고 한 평가 / ~의 평가 | '에 대한'의 남용 |
| 다양한 해석이 시도됐어요 | 해석이 여럿 나왔어요 / 세 갈래로 읽혔어요 | 상투어 대신 수와 구체어 |
| ~할 수 있어요(남발) | ~해요 / ~일지도 몰라요 | 완곡의 남발을 줄인다. 다만 가능성 문장을 단정으로 바꾸지 않고, 불확실하면 그 이유를 쓴다 |
| 진정한 광장 | (원문 인용이면 유지) 아니면 구체 명사 | 상투어 |
| ~하고 있어요 | ~해요 | 진행형 직역 |
| (모든 '에 대한'을) ~를 향한 | ~를 두고 한 / ~의 / ~를 둘러싼 / 동사로 풀기 | 기계적 치환은 새 번역투가 된다 |
| ~한다 / ~합니다(안내문) | ~해요 / ~를 먼저 확인하세요 | 해요체 통일 |
| 이용하시겠어요? | 이용할까요? | 과한 경어 |

## 4. 기계 점검 (`tools/ko_lint.py`)

## 5. 가드 고정 문구 (바꾸지 않음, 운영 봇과 조율 대상)

- tests/test_guards.py의 픽스처 문장(해요체)은 테스트 입력이므로 바꾸지 않는다.
