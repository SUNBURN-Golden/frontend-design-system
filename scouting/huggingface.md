## 결론 (현실적 평가)

1. **우리 작업에 도움이 되는 HF 자산은 없다**고 판단합니다. UI 관련 HF 자산은 (a) 스크린샷→코드 생성 학습·벤치(WebSight, Design2Code, WEBGEN/UIGEN)와 (b) GUI 조작 에이전트(OmniParser, UI-TARS, ShowUI)가 대부분입니다. 둘 다 "좋은 UI를 설계하고 검증"하는 우리 일과 방향이 다릅니다 `[추정]`.
2. **UI 품질 점수 모델(UIClip)이 가장 가깝지만** 영어 전용, 224px 입력, 전반 품질 점수라서 "글을 줄였는지, 한눈에 파악되는지, 한국어 위계가 맞는지"를 재지 못합니다. 설치 무게(605MB 가중치 + PyTorch)도 이득 대비 큽니다.
3. 직관성 평가는 **DOM과 렌더 측정**이 더 정확합니다. 이번 파일럿에서 `scan_metrics.py`가 첫 화면 단어 수, 글자 크기 종류, 클릭 요소 수, 터치 목표 크기, 아이콘 단독 버튼 수를 재현 가능하게 측정했습니다(§github.md 0장). 모델 점수보다 설명 가능하고 회귀 검사에 쓸 수 있습니다.
4. 큰 모델·데이터셋은 용량, 라이선스(qwen-research, 혼합 GPL, license other), 외부 전송 위험 때문에 모두 제외했습니다.
5. 재검토 조건: 한국어 UI 사용성 평가 데이터가 공개되거나, Apache/MIT 라이선스의 소형(<1GB) 한국어 지원 UI 평가 모델이 나오면 다시 봅니다.
